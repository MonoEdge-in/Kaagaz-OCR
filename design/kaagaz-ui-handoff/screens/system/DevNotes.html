01 · File structure

One module per component

Tokens are global (imported once in app/layout.tsx). Every component reads only var(--k-…) tokens, never hex values. Class names in kaagaz.css map to module class names by dropping the k- prefix: .k-btn--primary becomes styles.primary in Button.module.css.

Fonts load through next/font/google: Archivo (wdth 100–125, 400–700; set font-stretch 112%), IBM Plex Sans (400, 500, 600), IBM Plex Sans Devanagari (400, 500, 600), IBM Plex Mono (400, 500). Expose them as --k-font-display, --k-font-body, --k-font-mono on html.

02 · Theming

data-theme on html

  1. Three choices in the account menu: Light, Dark, System. Store the choice on the user’s profile so it follows them across devices.
  2. System follows prefers-color-scheme and updates live when the OS changes.
  3. Set data-theme on html before first paint (a tiny inline script in the head) to avoid a flash of the wrong theme.
  4. Never write a colour that exists in only one theme. A new token goes into both blocks in the same commit.
  5. Document pages keep --k-paper (light) in dark mode; marks on paper use the fixed --k-mark-* tokens.
